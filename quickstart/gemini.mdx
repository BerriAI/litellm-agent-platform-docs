The `lap` CLI talks to a running LAP instance. If you haven't deployed one yet, see [Installation](/installation).

<Note>
  First time? Install the CLI:

  ```bash
  git clone https://github.com/BerriAI/litellm-agent-platform.git
  cd litellm-agent-platform/cli && npm install
  ln -sf "$PWD/bin/lap.mjs" ~/.local/bin/lap
  ```
</Note>

## 1. Log in

```bash
lap login
```

Paste your LAP URL and `MASTER_KEY` when prompted. Saved to `~/.lap/config.json`.

## 2. Open an agent

```bash
lap
```

Pick your Gemini agent from the interactive list. `lap` spins up a Kubernetes-sandboxed pod running the [Google Gemini CLI](https://github.com/google-gemini/gemini-cli) in `--yolo` mode, wraps it in a `tmux` session so it survives WS reconnects (`lap --resume <id>` lands you on the same in-progress REPL), and attaches your local terminal to its TTY over a WebSocket.

Press **Ctrl-D** to detach — the session stays alive for 24h.

## Creating an agent

Unlike the other harnesses, Gemini doesn't speak OpenAI protocol, so it can't transparently route through your LiteLLM gateway as `OPENAI_BASE_URL`. You have two ways to authenticate:

### Option A — Vertex AI service account (recommended)

The cleanest path. Bring a Google Cloud service account JSON, stash it in a private gist, point the agent at it via `repo_url`. The harness clones it into `/work/repo/key.json` and auto-derives the Vertex AI config from the JSON itself — no per-agent env-var wiring needed.

```bash
# 1. Put your SA JSON in a secret gist
gh gist create --secret /path/to/sa-key.json -d "lap-gemini-sa"
# → https://gist.github.com/<you>/<gist-id>

# 2. Create the agent pointing at it
curl -X POST $LAP_URL/api/v1/managed_agents/agents \
  -H "Authorization: Bearer $MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name":"my-gemini",
    "harness_id":"gemini",
    "model":"gemini/gemini-2.5-flash",
    "repo_url":"https://gist.github.com/<you>/<gist-id>.git",
    "branch":"main",
    "env_vars":{"GITHUB_TOKEN":"<your gh token>"}
  }'
```

On boot the entrypoint:
- Clones the gist to `/work/repo/` (yielding `/work/repo/key.json`)
- Exports `GOOGLE_APPLICATION_CREDENTIALS=/work/repo/key.json`
- Exports `GOOGLE_GENAI_USE_VERTEXAI=true`
- Extracts `project_id` from the JSON into `GOOGLE_CLOUD_PROJECT`
- Defaults `GOOGLE_CLOUD_LOCATION=us-central1`
- Sets `GEMINI_CLI_TRUST_WORKSPACE=true` (skips the trust-folder dialog)
- Unsets `HTTPS_PROXY` (the gemini-cli's bundled `HttpsProxyAgent` constructor throws when proxy env is set; SA-derived OAuth tokens go direct to Google)

The CLI picks all of this up automatically. The first `lap` attach lands you straight at the chat prompt.

### Option B — BYO Gemini API Key

If you have an AI Studio key (the `AIzaSy…` shape, mint one at [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)), pass it via `env_vars`:

```bash
curl -X POST $LAP_URL/api/v1/managed_agents/agents \
  -H "Authorization: Bearer $MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name":"my-gemini",
    "harness_id":"gemini",
    "model":"gemini/gemini-2.5-flash",
    "env_vars":{"GEMINI_API_KEY":"AIzaSy…"}
  }'
```

The vault sidecar mints a stub for the key, the gemini-cli sends the stub on the wire, and the vault MITM swaps it back for the real value before the request reaches `generativelanguage.googleapis.com`. The agent process never sees the plaintext key.

## Picking a model

Gemini CLI auto-selects a model that may not be available on your project (we've seen it default to `gemini-3-flash-preview` and 404 on most Vertex projects). Pass `-m` explicitly inside the TUI if needed:

```
/model gemini-2.5-flash
```

Models known to work broadly on Vertex AI: `gemini-2.5-flash`, `gemini-2.5-pro`, `gemini-2.0-flash`.

## Smoke-testing without the TUI

The entrypoint has an optional non-interactive self-test path. Set `GEMINI_SELFTEST_PROMPT` (any value) in the agent's `env_vars` and the pod runs `gemini -p` once at boot, with the reply landing in `pod_logs_tail.text` on `/api/v1/managed_agents/sessions/<id>/diagnose`. Useful when validating fresh credentials or chasing platform regressions without needing the WebSocket `/tty` flow.

```bash
curl $LAP_URL/api/v1/managed_agents/sessions/<sid>/diagnose \
  -H "Authorization: Bearer $MASTER_KEY" \
  | jq -r '.pod_logs_tail.text'
# →
# [selftest] running: gemini -m gemini-2.5-flash -p "Reply with exactly four words: hello from gemini cli"
# [selftest-begin]
# hello from gemini cli
# [selftest-end]
```
