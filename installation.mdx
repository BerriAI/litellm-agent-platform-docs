## Quick local dev (no Kubernetes)

The fastest way to get a running platform is to skip Kubernetes entirely and
run the harness directly on your laptop. This works for `claude-agent-sdk` and
`opencode` agents — both use an HTTP JSON API, so no sandbox pod is needed.

**Prerequisites:** Node 20+, a Postgres instance, a LiteLLM gateway URL + key.

```bash
git clone https://github.com/BerriAI/litellm-agent-platform.git
cd litellm-agent-platform
cp .env.example .env
```

Add to `.env`:

```dotenv
DATABASE_URL="postgresql://..."     # direct (non-pooled) connection
MASTER_KEY=sk-local-dev
LITELLM_API_BASE="https://gateway.litellm.ai/"
LITELLM_API_KEY="sk-..."
ENCRYPTION_KEY=<base64 32-byte key>  # node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
LOCAL_SANDBOX_URL=http://localhost:4096
WARM_POOL_SIZE=0
IN_CLUSTER=false
```

Start the platform and the harness:

```bash
# Terminal 1 — platform
npm install && npm run dev          # http://localhost:3000

# Terminal 2 — harness
cd harnesses/claude-agent-sdk
npm install && npm run build
REPO_DIR=/path/to/any/local/repo \
LITELLM_API_BASE=https://gateway.litellm.ai/ \
LITELLM_API_KEY=sk-... \
node dist/server.js                 # http://localhost:4096
```

Point `lap` at the local instance:

```bash
lap login   # URL: http://localhost:3000, key: sk-local-dev
lap my-sdk-agent
```

Sessions reach `ready` in under 2 seconds. For the full local dev guide
including Apple Silicon quirks, see
[CONTRIBUTING.md](https://github.com/BerriAI/litellm-agent-platform/blob/main/CONTRIBUTING.md).

<Note>
  `LOCAL_SANDBOX_URL` tells the platform to skip K8s and route every session
  to the local harness. `WARM_POOL_SIZE=0` prevents the reconciler from trying
  to pre-provision pods.
</Note>

## Local with Kubernetes (kind)

Sandboxes run on Kubernetes via the [agent-sandbox CRD](https://github.com/kubernetes-sigs/agent-sandbox). Use this path for TTY harnesses (`claude-code`, `codex`) or to match production behaviour.

**Prerequisites:** Docker Desktop, `kind`, `kubectl`, `helm`, a LiteLLM gateway URL + key.

```bash
git clone https://github.com/BerriAI/litellm-agent-platform.git
cd litellm-agent-platform
cp .env.example .env   # fill in DATABASE_URL, MASTER_KEY, LITELLM_API_BASE, LITELLM_API_KEY
bin/kind-up.sh
docker compose up
```

`bin/kind-up.sh` is idempotent — provisions a kind cluster `agent-sbx`,
installs the sandbox controller, and loads the harness image. `docker compose up`
boots Postgres, runs the migration, and starts web (`:3000`) + worker.

Open [localhost:3000](http://localhost:3000), sign in with `MASTER_KEY`, create
an agent. Then jump to the [Claude Code quickstart](/quickstart/claude-code).

<Note>
  `DATABASE_URL` must be a direct (non-pooled) Postgres connection. Prisma migrations need advisory locks that pgbouncer blocks.
</Note>

## Tear down

```bash
kind delete cluster --name agent-sbx
```

## Production

Recommended: AWS EKS for the sandbox cluster, Render for web + worker.

- `bin/eks-up.sh` provisions the EKS cluster with the right node groups and the sandbox controller installed.
- `deploy/render/README.md` includes a Render Blueprint — one click to deploy web + worker.

### Required env vars

| Variable | Description |
|---|---|
| `DATABASE_URL` | Direct Postgres connection string. |
| `MASTER_KEY` | API authentication secret. |
| `LITELLM_API_BASE` | LiteLLM gateway URL. |
| `LITELLM_API_KEY` | LiteLLM gateway key. |
| `BASE_URL` | Public URL of the LAP deployment. |
| `ENCRYPTION_KEY` | Base64-encoded 32-byte key. Generate: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` |

<Warning>
  Never set `K8S_SKIP_TLS_VERIFY=true` against a production cluster — it disables TLS verification entirely.
</Warning>
